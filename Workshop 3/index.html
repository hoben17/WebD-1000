About this practice space

Start with structure. Add intention.

You do not need a perfect mockup to begin. Start with meaningful content, give it a clear hierarchy, then create a few rules you can reuse.

  1. Structure: use header, main, sections and footer to describe the page.
  2. Hierarchy: give headings, body copy and actions distinct jobs.
  3. Consistency: connect repeated choices with design tokens.

One layout. A handful of tokens. A system you can explain.

01 / Project brief

Write a brief for a website project.

  1. Purpose: Why does this website need to exist? Name its main goal and the action visitors should take.
  2. Audience: Who is it for, and what information or task brings them to the website?
  3. Pages and features: What is needed for the first release? List the pages and functions, and say what is out of scope.
  4. Content: What text, images and logos are needed? Name who will supply them and when.
  5. Design and requirements: Note the brand or tone, mobile and keyboard needs, and any required platform or hosting.
  6. Delivery: Agree a deadline, budget or time limit, what will be handed over, and who approves and maintains the website.
  7. Success: Describe one observable result or a simple task you can test with a visitor.

Start with: Build [website] for [audience] so they can [main action]. Include [pages and features]; leave out [not included]. [Owner] supplies [content] by [date]. Deliver [website or files] by [deadline] within [budget or time limit]. Check success by [test].

Example: a small café website

Build a three-page website for local customers to check the menu and plan a visit. Include Home, Menu and Visit pages with opening hours, an address and a map link; online ordering is out of scope. The owner supplies the logo, menu and photos in week one. Use the café's existing branding and support phones and keyboard use. Hand over HTML/CSS files within two weeks and the agreed budget; the owner approves the content and arranges updates. Test whether a new visitor can find today's opening hours and the menu without help.

Before moving on: Agree the brief with the project owner. Mark unknowns as “to confirm”. Use the agreed pages and content to start your sitemap.

Optional further reading: Smashing Magazine: website planning and needs assessment.

The layout workshop

Grid and Flexbox. One connected system.

Start with normal document flow for headings and paragraphs. Add Grid when rows and columns need shared tracks; use Flexbox when content needs to align along a row or column. Resize this page to compare both systems.

1. Grid gives the page a structure.

  2. Find the 8 / 4 split and the three equal cards.
  3. Change the grid gap in the studio, then compare again.

  }
  .sample-demo-main, .sample-demo-aside,
  .sample-demo-card { grid-column: auto; }
}

2. Flexbox lets content find its fit.

Flexbox works along one main axis at a time. A row follows the inline direction; a column follows the block direction. With wrapping, each new line distributes its own space independently.

A wrapping topic row

Explore a topic
HTMLCSS GridFlexbox

The title and topics use space-between on the main axis and center on the cross axis. Gap keeps a minimum separation; flex-wrap moves items onto another line when space runs out.

A flexible content row

Aa
Let the words take the space.

The marker keeps its width. This text grows into available space, shrinks when needed and wraps below the marker when its basis no longer fits.

flex: 1 1 12rem means grow: 1, shrink: 1, basis: 12rem. min-width: 0 allows the text item to shrink below its automatic minimum.

Try this

Follow the axes.

  1. Compare 390 px and 1280 px previews. Watch the topics wrap.
  2. Change the grid gap: both Grid tracks and these Flexbox rows share that token.
  3. Inspect the lesson cards: Grid places each card; a column flex container pushes its final link down with margin-top: auto.

Use justify-content along the main axis and align-items across it. Changing flex-direction changes which axis each property controls. Keep the HTML in a meaningful reading order when wrapping.

How do I use this field guide?

Start with the brief, content map, wireframe and prototype before choosing a palette. Then choose a lesson, inspect the example and change one design decision in the studio. Compare the preview with the generated HTML and CSS. Write down what changed and why it helped.

What belongs in my review checklist?

Check a narrow viewport, long headings, keyboard focus, form labels and text contrast in both themes. Test intermediate widths too. Record anything that still needs a human review before sharing your work.

Can I learn from the exported page?

Yes. Save the HTML and its companion CSS together, open the page and trace a component class back to its design tokens. The planning artifacts, linked prototype, Grid, Flexbox and native menu work without a JavaScript framework.

Change one decision at a time. Compare before and after, test at another width, and write down the reason for your choice.
